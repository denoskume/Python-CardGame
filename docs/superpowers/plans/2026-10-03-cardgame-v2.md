# CardGame V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Recommended execution: native, in this session, after user review.

**Goal:** Deliver a polished, reliable Python desktop and browser edition of Rouge gagne, noir perd from one shared codebase.

**Architecture:** Keep the asynchronous Pygame loop and existing Pygbag/GitHub Pages delivery. Make game transitions explicit, share input/render geometry, cache visual resources, and consolidate persistence behind desktop/browser adapters. Preserve existing native browser typing and profile data while replacing runtime method patches incrementally.

**Tech Stack:** Python 3.12 CI, Pygame, Pygbag, unittest, FFmpeg for browser audio, GitHub Actions/Pages.

**Spec:** `docs/superpowers/specs/2026-10-03-cardgame-v2-design.md` (approved by user).

## Global Constraints

- One shared Python game; keep the title and credits for Denos Kume and Sena FUKABE.
- Three cards, exactly one red; identity never changes during a shuffle.
- One-time welcome balance 30, minimum bet 10, maximum base bet 1000, step 5, multipliers 1/2/3; fictitious credits.
- Reject unaffordable total stakes; freeze accepted stake; win adds one stake, loss/timeout subtracts one stake; settle once.
- Observation/shuffle/choice each last 10 seconds; paused time is excluded.
- Easy 420/420 ms, Normal adaptive 300/300 → 240/240 at 2 wins → 200/200 at 3 → 170/170 at 4+, Expert 150/150.
- Keep 200 history entries and existing profile/history storage keys; no automatic credit refill or cross-device synchronization.
- Validate 360×640, 390×844, 844×390, 960×630, 1440×900; touch targets at least 44 px.
- Source names and UI remain English as in the current application; French game title remains. No extra localization subsystem.
- Do not alter unrelated portfolio repositories, add multiplayer/accounts, or claim untested platform support.
- Use isolated execution checkout via using-git-worktrees; verify repository instructions and upstream changes first. Do not force-push the design branch: local and remote documentation commits have different SHAs but identical content.

## Review Focus

- Selection queued exactly at the deadline must lose by timeout (Task 1).
- Valid JSON with invalid field types must not crash profile/history loading or grant a corrupt existing profile another bonus (Task 2).
- Browser storage disabled or full must preserve in-memory gameplay and report the saving failure (Task 2).
- Resize or focus loss halfway through a swap must preserve card identity, destinations and active duration (Task 4).
- Name-field spaces, pasted Unicode and duplicate touch/mouse events must not pause or resolve the game twice (Task 5).

## File map and verification conventions

Keep `main.py` for platform initialization/loop, `game.py` for round lifecycle, `user.py`/`bet.py` for domain state, and `menu_input.py` for native text entry. Add `settings.py`, `storage.py`, `layout.py`, `theme.py`, and `game_statistics.py`. The latter name avoids shadowing the Python standard library.

Retire `web_history.py`, `player_profiles.py`, `dynamic_difficulty.py`, `desktop_menu.py`, `welcome_balance_ui.py`, `history_table.py`, `bet_avatar_return.py` only after equivalent behavior is integrated and tested. Existing tests that assert source snippets/install order must be replaced with behavioral checks rather than silently deleted.

Run tests from the repository root. Headless Pygame tests use `SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy` and temporary storage; never modify real player data. Test helpers in `tests/game_fixture.py` provide `make_game(balance=30, now_ms=0)` with fake clock, seeded randomness and isolated storage. Preserve source imports used by `python src/main.py` and Pygbag.
